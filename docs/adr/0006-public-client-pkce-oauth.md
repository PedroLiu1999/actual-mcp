# Public Client PKCE OAuth, Dynamic Client Registration (/register), and Explicit Redirect Allowlist

`actual-mcp` originally required pre-shared `OAUTH_CLIENT_ID` and `OAUTH_CLIENT_SECRET` environment variables and hardcoded Google redirect URI patterns to support the Google Gemini connector (ADR 0001). To achieve a zero-friction setup matching the Home Assistant MCP model for modern AI clients (Claude Desktop, Cursor, Gemini, and web-based agents), we retired mandatory pre-shared client credentials and switched to OAuth 2.1 PKCE with dual client support:

1. **Automatic Dynamic Registration (RFC 7591 `/register`)**: Clients that support dynamic client registration automatically register by `POST`ing their metadata and redirect URIs to `/register`, receiving an issued `client_id` (persisted in `/data/oauth-tokens.json`).
2. **On-the-Fly Dynamic Clients**: Clients that do not support dynamic registration can supply any dynamic `client_id` directly to `/authorize` and `/token` using OAuth 2.1 Public Client (`token_endpoint_auth_methods_supported: ['none']`).
3. **Explicit Redirect URI Allowlist & Well-Known Callbacks**: Security is enforced by requiring the `OAUTH_ADMIN_PASSWORD` on the browser consent screen and restricting authorization redirects to `OAUTH_ALLOWED_REDIRECT_URIS` in `.env`. By default, well-known callback endpoints (`http://localhost`, `http://127.0.0.1`, Google Gemini `https://oauth-redirect.googleusercontent.com/r/`, `https://oauth-redirect.googleusercontent.com/a/`, and Vertex AI `https://vertexaisearch.cloud.google.com/oauth-redirect`) are allowlisted. Loopback URIs match on any port per RFC 8252 §7.3, and trailing slashes allow path prefix matching for remote callbacks.
